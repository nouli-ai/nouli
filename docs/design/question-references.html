    01 / WHAT’S INCLUDED

    Question + saved answer.

    The reference brings in the selected question, its typed result, and the image inputs needed to interpret it. The latest answer remains included automatically. An older reference adds to it.

    02 / WHICH VERSION

    Bind the answer you picked.

    Two turns can share a question ID and have different answers. Show both. A chosen reference keeps its source turn, so a later update never changes its meaning.

    03 / YOUR CURRENT DRAFT

    Keep the draft as it is.

    Referencing a Score result doesn’t switch a Choose one draft to Score. It doesn’t replace the prompt, options, or levels. Shift-Tab still changes the type; Tab still moves fields.

    The details that make it predictable.

    Proposed behavior shared by all three designs.

    Search by wording or ID, without learning a grammar

    Start typing after @. Match question text or paste a question ID; a short unambiguous ID prefix is enough to find candidates. IDs appear when relevant to the search and in source details. A question ID may match several saved turns: picking an answer is always explicit. The picker starts with recent answers across every session in the selected local store, including independent sessions, branch ancestors, and workflow decisions. Results show the source session and turn.

    Enter inserts; it doesn’t send in the same keystroke

    While results are open, ↑/↓ chooses a result and Enter inserts it. Esc closes the picker and leaves the typed text editable. Tab closes it and moves to the next field without accepting a candidate. Shift-Tab closes it and changes the answer type left to right. After selection, the usual Enter behavior resumes: send from Question or ready Context; add a row in Options/Levels, with a second consecutive Enter on the empty row to send.

    A normal @ stays normal text

    An @ at a word boundary opens suggestions; an email such as me@example.com doesn’t. Pasting an email or arbitrary prose doesn’t create a binding. Only choosing a saved answer creates a reference. No match gives “No saved question found” with an option to keep the literal text. Unselected text never secretly points to a result. A send shortcut with search open asks you to select or dismiss it first.

    Latest, duplicates, and repeated questions

    The latest question is labelled “already included.” Referencing it adds a readable inline label but doesn’t add the source twice. Choosing the same saved answer twice also shares one context source. Different turns of the same question remain separate sources. Short labels show a turn number when needed to disambiguate; full question and source IDs stay in details.

    Inspect and remove references without fighting the terminal

    In the proposed TUI, arrow keys move over an inline reference as one unit; Backspace or Delete removes the whole reference. A focused reference offers an explicit inspect action such as Ctrl-O, opening its question, answer and source turn. The browser demo’s labels are clickable for review, but the native design keeps mouse capture disabled so text selection continues to work.

    What happens if the referenced evidence won’t fit?

    Selected answers are required for that submission, including their needed image dependencies. If required evidence exceeds model capacity, keep the draft and identify the references that need to be removed. Don’t silently send a weaker request. A refused or failed source is identified as having no usable saved answer and cannot be selected as answer evidence.

    Other sessions and saved references

    Accepted scope: search all saved decisions across the selected local store, regardless of session or working directory. Show source session names and saved turns in results. Selecting a source adds that exact answer as evidence without merging the session’s history or active facts. Bind each reference to a saved turn and question together; preserve that binding when a draft is restored and record it with the submitted turn for inspection. This is a proposed addition, not existing @ support.

    The latest-context cue, filename-only images, Citrus question/answer colors, and Tab / Shift-Tab behavior already exist on the context-and-image-labels branch. The @ interactions shown here are proposals.
