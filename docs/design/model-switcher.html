    01 / SCOPE

    Session choice. Global shortlist.

    Enter remembers the selected pair for the current session, including reopening it. The catalog and shortlist are shared across workspaces using the same configuration. “Set default for new sessions” is a separate explicit action.

    02 / IDENTITY

    Always name the provider.

    The same model can appear through different routes. Display provider + exact model ID; select them together. Never keep a new model paired with the previous provider by accident.

    03 / HISTORY

    Change the next decision.

    Switching doesn’t re-ask an earlier question or change a saved answer. During a request, the frozen model finishes its work; your selection is clearly labelled for the next request.

    The small decisions worth agreeing on.

    These rules apply to all three proposals.

    Keep Nouli’s keys predictable

    Ctrl-L and /model open the picker. Ctrl-P and Ctrl-Shift-P cycle the configured shortlist. Enter selects and returns to the draft; Esc cancels. Tab closes without selection and moves to the next form field. Shift-Tab closes and cycles Yes/No → Choose one → Score. Ctrl-S remains Send in the form and never saves a model preference or sends while a picker is open. Every normal letter types into search.

    Images, missing credentials, and unknown capabilities

    Show known image support when a draft includes an image, including images from required @ references. A known text-only model explains why it can’t handle the draft. Unknown support is labelled, without inventing a capability claim; ordinary send validation and provider responses still apply. A missing credential names the provider and offers its setup command, keeping the existing model until setup succeeds. “Configured” never promises a live service is reachable.

    Where the catalog comes from

    Combine compatible model IDs from configured providers, Nouli’s dated capability snapshot, previously served models, and provider discovery where a protocol supports it. Keep exact-ID entry available because the model settings tables are not an allowlist. Don’t assume every model available in pi supports Nouli’s typed decision protocols. The rows here are illustrative examples from repository fixtures, not an inventory of your account or a claim of current availability.

    Default changes should be visible

    Ordinary selection affects this session. The separate Defaults & shortlist view offers an explicit “Set default for new sessions” action and global shortlist membership. Changing the default doesn’t rewrite existing sessions or their saved answers. A picker selection is an explicit live override of the model selected at launch. The prototype simulates these settings only in page memory.

    A switch can still reveal a smaller context window

    Preserve the draft, then validate its required evidence against the newly selected model when sending. If it can’t fit, name the problem and keep the draft for correction or another model choice. Don’t silently drop selected @ answers, images, or the latest question. Show only limits Nouli actually knows; avoid unverified prices or speed rankings.

    What comes from pi

    Pi documents Ctrl-L for model selection and Ctrl-P / Ctrl-Shift-P for scoped cycling. Its selector supports search, Enter selection, cancellation, scope switching, and a separate default-saving action. Nouli’s key and scope choices above are proposals adapted to its existing form.

    What exists in Nouli today

    Nouli resolves provider and model, shows selected/served model status, freezes accepted requests, and stores provider credentials centrally. This HTML explores a new interactive switcher. The model list and credential states are example data; it does not change your app, settings, or sessions.
