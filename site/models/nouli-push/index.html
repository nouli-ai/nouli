Nouli Push

PushT keypoint control

Nouli Push is a keypoint-based policy for the PushT simulator. A fine-tuned Decoder Only Transformer (DOT) predicts action forecasts, and a causal controller combines past forecasts into legal XY actions.

Quickstart with Nouli CLI

Requires Python 3.12, the HF CLI, and Nouli CLI 0.4.2. Hugging Face hosts the files; inference runs on your machine. The Python server loads the weights, and Nouli runs the supplied decision workflow. No hosted API key is required.

In the first terminal:

Terminal 1 · prepare and serve
hf download nouli-ai/nouli-push --revision v1.0.0 --local-dir ./nouli-push
cd nouli-push
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python prepare.py --input-json examples/input.json
python serve.py --device cpu

Once the server reports ready, open a second terminal in nouli-push:

Terminal 2 · run the workflow
nouli --config nouli/nouli.toml --store ./.nouli-store \
  workflow run nouli/example-workflow.json --json

This example returns one action for the supplied state. Running an episode also requires the simulator loop to apply actions and provide each next state.

Base models and training data

  • IliaLarchenko/dot_pusht_keypoints_best

Training data: lerobot/pusht_keypoints; 206 demonstrations / 25,650 frames.

Adapted from DOT using demonstration actions and an original-policy anchor. The starter already used these demonstrations; evaluation uses fresh simulator initializations. Source revisions and provenance.

Limitations

  • Validated for numeric-keypoint control in PushT. Camera-input and real-world transfer are untested.
  • Use the supplied state normalization, history and action-grid interface.
