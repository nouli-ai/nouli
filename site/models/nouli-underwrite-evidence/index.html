Nouli Underwrite Evidence

Historical evidence for underwriting review

Organize historical construction-incident evidence into four review themes. Three local models combine their answers; separate rules route the supplied case for information, referral or human review.

Research preview for commercial underwriters and risk engineers. Requires a supplied supporting excerpt and separate current facts. People make final underwriting decisions.

How it works

The ensemble classifies the historical evidence. Separate rules check the supplied current facts, conflicts and delegated authority. Nouli connects these steps and records the workflow. Missing or conflicting required information bypasses the classifier; a person retains the final decision.

Model at a glance

Input An English historical incident narrative and a human-selected supporting excerpt

Themes Equipment/control integrity; Management/training; Work practice; Worksite condition

Handling incomplete information and referrals

The supplied cases also demonstrate the checks around the classifier:

Situation Recorded workflow behavior
Required facts are present Classify the historical evidence and apply the review rule.
Current-control information is missing Request information; skip classification.
Supplied current-control information conflicts Refer to an underwriter; skip classification.
Requested limit exceeds delegated authority Refer to senior-underwriter review.
Historical supporting evidence is absent Request information; skip classification.
The declared authority limit changes Apply the new rule to the same historical model input.

These are constructed rule demonstrations, not observed carrier decisions. The USD limits, 0.8 probability threshold and team mappings are illustrative. Recorded workflow cases.

Quickstart

Use Python 3.12 and the HF CLI. Download the complete repository:

Terminal
hf download nouli-ai/nouli-underwrite-evidence --revision v1.0.0 \
  --local-dir ./nouli-underwrite-evidence
cd nouli-underwrite-evidence
python3.12 verify_release.py
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python inference/predict.py --checkpoint . --device cpu \
  --text-file examples/model-input.txt --output outputs/prediction.json

The provided helper runs the complete ensemble. The root is a custom package; a raw Transformers pipeline or AutoModel call will not run all three models. All weights and tokenizers are included. No hosted API key or separate base download is required.

To run the evidence checks and routing through Nouli CLI 0.5.1:

Terminal
.venv/bin/python inference/nouli_demo.py --checkpoint . --device cpu \
  --nouli /absolute/path/to/nouli \
  --case examples/input.json --rules examples/portable/rules-v1.json \
  --output outputs/workflow.json

See setup and integration for preparing your own evidence packet, hardware requirements, offline use and the local provider endpoint.

Evaluation, base models and data

The supplied frozen evaluation records 86.79% macro-F1 and 91.06% accuracy on 123 examples from 106 source reports. Inputs include human-selected supporting excerpts. These results measure historical evidence-theme classification, not performance on raw submissions or underwriting outcomes. Evaluation scope and metrics.

Based on RoBERTa-large, TS-Ettin-150M and Ettin encoder 1B, using ConstructCIE, a human-annotated dataset of historical construction accident narratives. Pinned revisions and provenance.

Limitations

  • Requires a supplied, source-supported excerpt. Automatic evidence extraction and end-to-end processing of raw insurance submissions were not evaluated.
  • Historical incidents do not establish present controls. Current assertions must cite separate supplied documents; the workflow does not independently verify those assertions.
  • The benchmark is small and imbalanced, with few management/training examples in the held-out set. Performance across carriers, trades and document types remains unmeasured.
  • Each component has a finite input budget. Keep the relevant excerpt first and follow the supplied serialization; long context can be truncated.
  • Probabilities and the example review threshold are not guarantees of correctness. The rules require validation for the intended workflow.
  • Coverage, liability, regulatory compliance, pricing, acceptance and binding decisions are outside scope. No insurer or source-data publisher endorsement is implied.
