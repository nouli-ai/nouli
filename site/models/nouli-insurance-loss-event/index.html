Nouli Insurance Loss Event

Property-claim intake

Classify an initial property-claim notice across 22 loss-event categories, then suggest an intake queue. Explore recorded FNOL examples for claims handlers, intake teams and loss adjusters.

Research preview, evaluated on synthetic English household and building insurance notices. Coverage and settlement decisions are outside its scope.

How it works

The model identifies the loss event from the narrative. A separate, hand-authored rule maps its answer to a queue. The included Nouli workflow connects the two steps and records their execution.

Examples for claims handlers and loss adjusters

These constructed first-notice-of-loss (FNOL) examples cover all 22 model categories. Each result was recorded on CPU. Complete inputs, probabilities and queue outputs.

For an intake handoff, retain the original notice alongside the suggested event and queue. The reported cause matters: a broken window can follow hail, forced entry or an accidental impact. Policy coverage and settlement require a separate assessment.

Quickstart

Use Python 3.12 and the HF CLI. Download the complete repository:

Terminal
hf download nouli-ai/nouli-insurance-loss-event --revision v1.0.1 --local-dir ./nouli-insurance-loss-event
cd nouli-insurance-loss-event
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python predict.py --checkpoint . --device cpu \
  --text-file examples/notice.txt

Replace the example file with your own initial notice. The helper applies the release preprocessing and returns all 22 probabilities. No hosted API key or separate base-model download is required.

To run the two-step workflow through Nouli CLI 0.5.1:

Terminal
mkdir -p outputs
.venv/bin/python nouli_demo.py --checkpoint . \
  --nouli "$(command -v nouli)" --device cpu \
  --text "$(cat examples/notice.txt)" --output outputs/workflow.json

See setup and integration for CUDA, offline use, the routing rule and output fields.

Base model and data

Based on FacebookAI/roberta-large, with data from Gratex’s GNOTHEIA Synthetic Insurance Dataset v2. The dataset contains synthetic household and building claim scenarios. Source revisions and provenance.

The repository includes the complete selected classifier, tokenizer and local runtime. The workflow and queue mapping are application rules supplied with the example.

Limitations

  • Validated on synthetic English data. Performance on real insurer notices remains unmeasured.
  • Supports a fixed 22-category taxonomy. It always chooses a category for a valid narrative; unfamiliar or closely related events can be misclassified, including theft and burglary.
  • Inputs beyond 384 tokens are truncated. Keep the reported cause and circumstances near the beginning.
  • The 0.8 review threshold is illustrative; model probabilities do not guarantee correctness. Validate thresholds for your workflow.
  • Classifies the reported event; coverage, fraud, pricing and payout decisions are outside its scope.
