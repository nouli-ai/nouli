Nouli is a multi-turn decision harness: it gives a decision model a memory. You send facts and a question with a fixed set of answers; the model returns a probability for each answer. Nouli records the turn in a session, and the next turn only needs the new facts.

01Install

On macOS (Apple silicon), use Homebrew:

brew install standing-desks/tap/nouli

On Linux, use the download installer:

curl -fsSL https://standing-desks.github.io/nouli/install.sh | sh

The script installs the latest published binary into ~/.local/bin after verifying its checksum. It also works on Apple silicon macOS. Linux needs glibc 2.38 or newer. The 0.1.0 downloads are ARM64-only; Linux x86_64 requires a newer release.

If your shell cannot find Nouli, add the installation directory to your PATH:

export PATH="$HOME/.local/bin:$PATH"
nouli --version

If you previously installed with Cargo, run cargo uninstall nouli-cli before switching so the old executable does not take precedence.

To update a Homebrew installation:

brew update
brew upgrade standing-desks/tap/nouli

For a script installation, run the download installer again. Uninstall with brew uninstall standing-desks/tap/nouli for Homebrew, or remove ~/.local/bin/nouli for the script. Your configuration and saved sessions are preserved.

See the installation guide for selecting a version, changing the installation directory, inspecting the script, and building from source.

02Configure a provider

Nouli reads ~/.nouli/config.toml. The first time you make a decision without one, Nouli creates an empty file and asks you to define a provider. For TypeSafe:

default_provider = "typesafe"
default_model = "jev-latest"

[providers.typesafe]
protocol = "typesafe"
base_url = "https://api.typesafe.ai"
api_key_env = "TYPESAFE_TOKEN"

api_key_env names an environment variable; never put the key itself in the file. Nouli reads .env from the directory you run it in, so you can keep the key there and out of version control:

TYPESAFE_TOKEN="your-api-key"

A value exported in your shell takes precedence. Use --env-file FILE to read a different file.

The other supported protocols are openai-decisions and openrouter-decisions. A local Laya service uses the typesafe protocol with a loopback URL and needs a context budget, because Nouli can't look up its limits:

[providers.local]
protocol = "typesafe"
base_url = "http://localhost:8000"

[providers.local.models."english"]
context_budget_tokens = 8192
reserved_output_tokens = 128

Pick a provider or model for one call with --provider NAME and --model MODEL. Each call uses your provider account and may cost money.

03Make a decision

Give the facts with --state (-s) and the questions with --questions (-q). --name starts a saved session:

nouli --name travel \
  -s 'The train costs 40 USD and arrives 30 minutes before the meeting.
A taxi costs 70 USD and also arrives in time. Prefer the cheaper option
that arrives on time.' \
  -q '[{"id": "transport",
        "prompt": "How should I travel to the meeting?",
        "answer_space": {"type": "choice", "options": [
          {"id": "train", "description": "Take the train"},
          {"id": "taxi", "description": "Take a taxi"}]}}]'
transport: choice: train (Take the train), P(selected)=1

Each question has one of three answer types:

typeansweranswer_space
choiceOne option, with a probability for every option{"type": "choice", "options": [{"id", "description"}]}
noulThe probability that the answer is yes{"type": "noul"}
scoreThe expected position on an ordered rubric, which can be fractional{"type": "score", "levels": ["Poor", "Adequate", "Excellent"]}

One turn can ask several questions; the model answers each independently. For larger requests, put the turn in a file and pass --input request.json (JSON or TOON). Answers are model judgments, not actions: Nouli never books, sends, or changes anything.

04Add a turn

--session continues a saved session. Send only what changed; the earlier facts and answers come along:

nouli --session travel \
  -s 'The train has been cancelled. The taxi is still available at 70 USD.' \
  -q '[{"id": "transport", "prompt": "How should I travel to the meeting now?",
        "answer_space": {"type": "choice", "options": [
          {"id": "train", "description": "Take the train"},
          {"id": "taxi", "description": "Take a taxi"}]}}]'

Sessions are saved under ~/.nouli and work from any directory. --store DIR uses a different store. --no-session makes a decision without saving it.

Long histories are trimmed to fit the model's context budget: older decisions shrink to their question and answer first, then the oldest optional records drop out. The full record stays in the store either way. nouli context SESSION shows exactly what reached the model for a turn.

05Branch and blend

--from starts a new session from saved history. One --from branches; several blend:

nouli --from travel --name travel-late -s '…' -q '…'
nouli --from travel --from budget --name plan -s '…' -q '…'

A new session captures its sources when you create it. Later turns in travel don't change plan; make a new blend to reconsider with the updated history. To start from an older point, name the turn: --from travel@TURN_ID. Combine --from with --no-session to try a what-if without saving anything.

06See the graph

nouli view --session plan
nouli view --session plan --mermaid > plan.mmd
nouli sessions list
nouli sessions show plan
nouli sessions export plan --format json > plan.json

nouli view draws the session and every turn it captured as boxes in your terminal, with ▶ marking each selected answer. --mermaid prints the same graph as Mermaid source; paste it into a ```mermaid block and GitHub draws it. None of these commands call a model or change the store.

07Run a workflow

When later questions depend on earlier answers, describe the turns as a graph and let Nouli run it. Nodes with no dependency between them run in parallel:

{
  "state": [],
  "nodes": [
    {"id": "choose", "turn": {
      "state": [{"type": "text", "text": "The train takes 4 hours; the flight takes 2 hours."}],
      "questions": [{"id": "route", "prompt": "Which route should I take?",
        "answer_space": {"type": "choice", "options": [
          {"id": "train", "description": "Take the train"},
          {"id": "flight", "description": "Take the flight"}]}}]}},
    {"id": "book", "dependencies": ["choose"], "turn": {
      "state": [],
      "questions": [{"id": "book_now", "prompt": "Given the preferred route, should I book it now?",
        "answer_space": {"type": "noul"}}]}}
  ]
}
nouli workflows run workflow.json --name review --parallel 2
nouli workflows show RUN_ID
nouli workflows resume RUN_ID

A run saves its graph and settings before it starts. If it's interrupted, resume reuses finished nodes and runs the rest. --jsonl streams progress events.

08Output and exit codes

Output is text in a terminal and JSON when piped. Choose explicitly with --format text|json|jsonl|toon, --json, or --jsonl.

exitmeaning
0Completed, including replays and per-question refusals
2Invalid input or configuration
3Provider, authentication, capability, contract, or capacity failure
4Partial or failed workflow
5Request, writer, context, or advanced-head conflict
6Storage, internal, or output failure
130Interrupted; recovery needed

09Troubleshooting

messagewhat to do
providers_requiredOpen the configuration file named in the error and add a [providers.NAME] section.
provider_requiredSet default_provider or pass --provider NAME.
model_requiredSet default_model or pass --model MODEL.
unknown_providerUse a provider name defined in your configuration.
credential_unavailableSet the environment variable named in the error, in your shell or the env file.
env_file_not_foundCheck the path passed to --env-file.
invalid_env_fileCheck assignments, quotes, and UTF-8 encoding in the env file.
invalid_model_budgetAdd context_budget_tokens under [providers.NAME.models."MODEL"] or pass --context-budget TOKENS.
invalid_configuration_syntaxCheck the TOML. Top-level settings go before provider sections.

A provider can refuse a single question; that's recorded as a refusal, not an error. Run nouli --help for every option. The reference docs cover each subsystem in detail.
