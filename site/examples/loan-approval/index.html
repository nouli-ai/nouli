Personal loan approval

In this recorded run, the model did not correctly apply the income correction. The graph preserves that result. Steps 7-9 explain the mismatch and the calculation a reviewer should check.

The problem

A loan officer is reviewing a request for a 6000 USD personal loan. The bank also offers a smaller 3000 USD alternative. A good repayment record is only one part of the review: either offer must leave enough money after living expenses, existing debts, and the new installment. During the review, corrected income verification arrives.

The OCC Installment Lending handbook describes reviewing repayment capacity after obligations and living expenses. The applicant, loan quotes, and thresholds here are fictional. They demonstrate selected review steps, not a complete underwriting or compliance process.

What we will do

We will keep verified cash flow, repayment history, and product policy in three separate histories. We will blend cash flow with policy to assess affordability, blend repayment history with policy to assess account performance, then combine both reviews into a recommendation. After income changes, we will create a new affordability review and recommendation while keeping the earlier results available.

Before you start

Configure a provider and model, then run the commands in order in the same shell. Nouli reads credentials from your shell or the .env in your current directory. Each decision calls your configured provider and may incur charges.

The outputs below were captured with typesafe/jev-1.14.0. They are a recorded run, not guaranteed results. Probabilities, session IDs, and model answers may differ when you run the commands.

Set a session prefix for this walkthrough. Change it before repeating the example so the new sessions have unique names:

example=loan

01Record verified household cash flow

Start with the verified income and existing expenses. This session has no product policy yet, so its question asks only about money available before a new loan payment.

nouli --format text --name "$example-cashflow" \
  --state 'Fictional application L-101, initial verification at 09:00: verified recurring
net income is 5000 USD per month. Essential living expenses are 3000 USD and
payments on existing debts are 600 USD. These expenses exclude any proposed new
loan. There are no other obligations. All figures are documented for this
sample.' \
  --questions '[
  {
    "id": "cashflow",
    "prompt": "What monthly amount remains before a new loan payment?",
    "answer_space": {
      "type": "choice",
      "options": [
        {"id": "s1400", "description": "1400 USD"},
        {"id": "s2000", "description": "2000 USD"},
        {"id": "missing", "description": "Request missing cash-flow records"}
      ]
    }
  }
]'

06Combine both reviews into a lending recommendation

Combine the two review sessions. Each source is already a blend, so the recommendation includes cash flow, repayment history, and the shared policy.

nouli --format text \
  --from "$example-affordability" \
  --from "$example-credit-review" \
  --name "$example-recommendation" \
  --state 'Combine the affordability and credit-history reviews using the sample product
policy. A passing history gate cannot override an affordability failure.
Prefer the requested 6000 USD loan if eligible; otherwise recommend the eligible
3000 USD alternative; otherwise refer for manual review. This is a recommendation
for a loan officer, not an executed lending decision.' \
  --questions '[
  {
    "id": "recommendation",
    "prompt": "What should the loan officer review?",
    "answer_space": {
      "type": "choice",
      "options": [
        {"id": "requested", "description": "Recommend the requested 6000 USD loan at the quoted 250 USD installment"},
        {"id": "smaller", "description": "Recommend review of the 3000 USD alternative at the quoted 150 USD installment"},
        {"id": "manual", "description": "Refer for manual review without recommending either loan"}
      ]
    }
  }
]'
