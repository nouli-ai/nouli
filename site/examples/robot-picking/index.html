Examples

Robotic picking exceptions

A picking robot continues one Nouli session through a pick that goes wrong: a failed grasp, an uncertain next move, a double pick, and a torn bag. Each sensor update is a new turn, and the robot uses the returned probabilities to decide when to ask a person.

The problem

A robotic picking arm handles most items without help. The cost and the risk sit in the exceptions: suction cups that seal on loose packaging, two items lifted together, damaged goods. Each exception is a decision made with partial information while the arm holds an item, and often a reason to call a remote operator, which costs time.

A decision layer for these moments needs memory of the whole pick so far, typed answers the controller can act on, and probabilities it can use to decide when not to act alone. When something goes wrong, the team also needs to replay exactly what the robot knew at each step.

Nouli makes these task-level decisions, one model call each. Motion planning, grasp execution, and safety-rated stops stay in the robot's real-time control stack. The item, station, order, and rules here are illustrative.

What we will do

We load the item's grasp history and the station rules as separate sessions, then start the pick as a blend of both. The robot adds each sensor update to that one session. We check an alternative outcome without saving it, and finish by blending the episode with the item history to update the item's grasp profile.

Before you start

Configure a provider and model, then run the commands in order in the same shell. Nouli reads credentials from your shell or the .env in your current directory. Each decision calls your configured provider and may cost money.

The outputs below were recorded with typesafe/jev-1.14.0. Your probabilities, session IDs, and answers may differ.

Set a session prefix for this walkthrough. Change it before running the walkthrough again, so the new sessions get unique names:

example=pick
show the steps as

Open nouli open catalog. Add each step’s context, question and answers in the form, then press Enter to send. Captures replay the recorded model answers in the current TUI.

What the graph keeps

The pick session holds the whole episode in order: the scene, the failed grasp, the double pick, and the operator's report. Every answer records the context it was based on, so a failure review can see that the robot asked for help at 1.00 once the weight was wrong, instead of placing the load. These commands make decisions only; they don't move an arm.
