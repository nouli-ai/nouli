Robotic picking exceptions

A picking robot continues one Nouli session through a pick that goes wrong: a failed grasp, an uncertain next move, a double pick, and a torn bag. Each sensor update is a new turn, and the robot uses the returned probabilities to decide when to ask a person.

The problem

A robotic picking arm handles most items without help. The cost and the risk sit in the exceptions: suction cups that seal on loose packaging, two items lifted together, damaged goods. Each exception is a decision made with partial information while the arm holds an item, and often a reason to call a remote operator, which costs time.

A decision layer for these moments needs memory of the whole pick so far, typed answers the controller can act on, and probabilities it can use to decide when not to act alone. When something goes wrong, the team also needs to replay exactly what the robot knew at each step.

Nouli makes these task-level decisions, one model call each. Motion planning, grasp execution, and safety-rated stops stay in the robot's real-time control stack. The item, station, order, and rules here are illustrative.

What we will do

We load the item's grasp history and the station rules as separate sessions, then start the pick as a blend of both. The robot adds each sensor update to that one session. We check an alternative outcome without saving it, and finish by blending the episode with the item history to update the item's grasp profile.

Before you start

Configure a provider and model, then run the commands in order in the same shell. Nouli reads credentials from your shell or the .env in your current directory. Each decision calls your configured provider and may cost money.

The outputs below were recorded with typesafe/jev-1.14.0. Your probabilities, session IDs, and answers may differ.

Set a session prefix for this walkthrough. Change it before running the walkthrough again, so the new sessions get unique names:

example=pick

01Load the item's grasp history

Load what the station knows about this item into its own session. Every pick of this SKU can start from it.

nouli --format text --name "$example-catalog" \
  --state 'Illustrative item record: SKU 30418 is a 400 ml shampoo bottle in a clear polybag, weighing 0.45 kg. At this station this month the arm picked it 112 times. Suction on the flat label area succeeded first time in 81 of those picks. Most failures happened when the suction cup sealed on loose bag film instead of the bottle.' \
  --questions '[
  {
    "id": "grasp",
    "prompt": "Which grasp should the arm prefer for this item?",
    "answer_space": {
      "type": "choice",
      "options": [
        {
          "id": "suction_label",
          "description": "Suction on the flat label area of the bottle"
        },
        {
          "id": "suction_any",
          "description": "Suction on any flat bag surface"
        },
        {
          "id": "pinch",
          "description": "A two-finger pinch on the bottle neck"
        }
      ]
    }
  }
]'

02Load the station rules

Load the station rules into a second session. The first rule is about uncertainty: the robot's controller reads the probability Nouli returns and acts on its own only at 0.6 or above.

nouli --format text --name "$example-policy" \
  --state 'Illustrative station rules for the picking arm: the arm acts on its own only when its chosen action has a probability of at least 0.6; otherwise a remote operator chooses. After two failed grasps on one item, stop and request remote assistance. Never place a load whose measured weight differs from the expected item weight by more than 15%. A torn or open bag goes to the exception station, never into a shipping box.' \
  --questions '[
  {
    "id": "overweight",
    "prompt": "May the arm place a load that weighs 1.9 kg when one 0.45 kg item is expected?",
    "answer_space": {
      "type": "noul"
    }
  }
]'

Output

The model confirms that a 1.9 kg load can't be placed when one 0.45 kg item is expected (P(yes)=0.04). That rule matters three turns later.

03Start the pick

Start the pick as a blend of the item history and the station rules. From here the robot continues one session, adding each sensor update as a new turn.

nouli --format text --from "$example-catalog" --from "$example-policy" --name "$example-pick" \
  --state 'Task: pick one unit of SKU 30418 for order 4471 into box B-12. Tote camera: 6 items. The target is detected with confidence 0.82, lying label-down, partly under another polybagged item. The only flat surface visible on it is 3 square centimeters of loose bag film.' \
  --questions '[
  {
    "id": "action",
    "prompt": "What should the arm do first?",
    "answer_space": {
      "type": "choice",
      "options": [
        {
          "id": "nudge",
          "description": "Nudge the covering item aside to expose the target's label"
        },
        {
          "id": "suction_film",
          "description": "Attempt suction on the visible bag film"
        },
        {
          "id": "assist",
          "description": "Request remote assistance now"
        }
      ]
    }
  }
]'

04React to a failed grasp

05Check a clean lift without saving

Before saving the real outcome, check what the arm would do if the operator's pinch lifted one bottle cleanly. --no-session evaluates it without saving.

nouli --format text --from "$example-pick" --no-session \
  --state 'What-if: the remote operator chooses a pinch on the bottle neck, and pinch attempt 2 lifts the target. The wrist force sensor reads 0.46 kg against an expected 0.45 kg, and the tote camera shows a single bottle in the gripper.' \
  --questions '[
  {
    "id": "load",
    "prompt": "What should the arm do with the load?",
    "answer_space": {
      "type": "choice",
      "options": [
        {
          "id": "return_assist",
          "description": "Lower the load back into the tote and request remote assistance"

          "id": "shake",
          "description": "Shake the load to check for anything attached, then place it"

08Update the item's grasp profile

Blend the item history with the whole pick episode to decide how the arm should grasp this SKU next time. One robot's episode becomes station knowledge without changing the original item session.

nouli --format text --from "$example-catalog" --from "$example-pick" --name "$example-catalog-review" \
  --state 'Review the completed pick against the item'\''s history and decide how the arm should grasp this SKU next time.' \
  --questions '[
  {
    "id": "profile",
    "prompt": "How should the grasp profile for SKU 30418 change?",
    "answer_space": {
      "type": "choice",
      "options": [
        {
          "id": "pinch_first",
          "description": "Prefer a neck pinch, and check the weight before placing"
        },
        {
          "id": "keep",
          "description": "Keep suction on the label area as the first choice"

          "description": "Always request remote assistance for this item"

      ]
    }

What the graph keeps

The pick session holds the whole episode in order: the scene, the failed grasp, the double pick, and the operator's report. Every answer records the context it was based on, so a failure review can see that the robot asked for help at 0.54 instead of guessing. These commands make decisions only; they don't move an arm.
